nvim-zh                                                         *nvim-zh*

nvim-zh is a Simplified Chinese localization plugin for Neovim. It integrates
native gettext messages, Chinese Help, exact Lua catalogs, and common UI.
Localization packs add support for third-party plugins and clangd display text.

It does not rewrite editing buffers, raw diagnostic/LSP objects, third-party
source files, private rendered UI, or external tool byte streams. Unknown text
falls back to English.

REQUIREMENTS AND INSTALLATION                     *nvim-zh-setup* *nvim-zh-install*

Neovim 0.12+ is required for the supported vim.pack installation and update
workflow. Users do not need Python, msgfmt, helptags, or a build hook.

The translation baseline is Neovim 0.12.6. Automatic native gettext binding
currently requires Linux/glibc + LuaJIT; other environments report a native
degradation while Chinese Help and Lua UI remain available.

Install and enable with: >lua

    vim.pack.add({ 'https://github.com/DerckHanna/nvim-zh' }, { load = true })
    require('nvim-zh').setup()
<
Core resources ship with the main package. setup validates and activates them
offline. Catalog refresh and pack download contact the release source.
Previously downloaded packs can be imported offline.

COMMANDS                                                     *nvim-zh-commands*

*:NvimZh*        Open or focus the Chinese panel.
*:NvimZhPacks*   Open package management or run a subcommand. See
                  |nvim-zh-packs|.
*:NvimZhCheck*   Show read-only health results. Also available through
                  `:checkhealth nvim-zh`.

There are no separate Update, Rollback, Reload, Info, or Missing commands.
Structured data is available through |nvim-zh-api| instead of notification
scraping.

PANEL AND UPDATES                                              *nvim-zh-panel*

:NvimZh opens overview, package management, translation, missing-entry, and
health pages. Tab/Shift-Tab switch pages, j/k scroll or select, / searches,
? opens help, and q/Esc closes the panel.

Update the core plugin through vim.pack: >lua

    vim.pack.update()
<
Use :write in the standard vim.pack confirmation buffer. Cancelling leaves the
active resources unchanged. Confirmed changes automatically synchronize MO,
the core UI catalog and Chinese Help.

Pure resource changes affect subsequent queries without a restart. An
implementation change is reported as restart_required and completes
automatically on the next startup. Invalid candidates preserve the previous
verified resource set. Version rollback uses vim.pack and its lock file.

LOCALIZATION PACKS                                            *nvim-zh-packs*

On the packs page, press Enter to fetch the initial catalog, r to refresh,
/ to filter, and j/k to select a pack. Enter opens details and available
actions. i installs, u updates one pack, U previews updates for installed
packs, and a opens page actions including local import. Use pack details to
pause, resume, roll back, or uninstall a pack.

Downloads continue when the panel closes. Open it again to see progress.
Catalog-only updates can apply immediately. Adapter changes may require a
restart.

:NvimZhPacks also accepts list, search, install, update, enable, disable,
rollback, and remove. Use telescope@1.0.0 to select a specific version.
Use `:NvimZhPacks import FILE` for local data packs, or
`:NvimZhPacks! import FILE` to explicitly permit a local Lua entry point.

CONFIGURATION                                                 *nvim-zh-config*

The default configuration is: >lua

    require('nvim-zh').setup({
      modules = {
        core = { enabled = true, apply_language = true },
        help = { enabled = true, lang = { 'cn', 'en' } },
        ui = { notify = true, prompts = true, select_items = false, echo = false },
        plugins = { auto = true, lazy_load = true, disabled = {} },
        diagnostics = {
          enabled = true,
          virtual_text = true,
          virtual_lines = true,
          float = true,
          lists = true,
        },
        lsp = { messages = true, progress = true, hints = true },
      },
      overrides = {},
      missing = { enabled = true, max_entries = 2000 },
    })
<
modules.core controls only native gettext integration. enabled=false disables
it; apply_language=false opts out of automatic MO binding and message-language
selection. Chinese Help and Lua UI are independent.

modules.help selects 'helplang' with English Help as fallback.
modules.ui controls notify, input/select, optional select
item formatting, and opt-in echo. modules.plugins.auto adapts loaded supported
plugins without forcing the plugins themselves to load; disabled is an array of
adapter names.

Diagnostic formatters call a user formatter first and preserve nil suppression,
errors, raw diagnostics, ranges, codes, and user_data.lsp. LSP wrappers copy only
display fields and preserve actions, tokens, progress values, and cancellation.

Overrides are data indexed by domain, explicit context, and source msgid: >lua

    overrides = {
      ['my-plugin'] = {
        [''] = { Save = '保存' },
        menu = { Open = '展开' },
      },
    }
<
Functions and executable rules are not catalog data. Buffer, Window, and
Register use the preserve terminology policy; no global runtime terminology
replacement is performed.

Optional hot configuration is `stdpath('config') .. '/nvim-zh.json'`: >

    {"schema":1,"modules":{"ui":{"notify":false}}}
<
Precedence is defaults < setup(opts) < local JSON. Lists replace lists. Saving
validates and applies the file; invalid input or a failed application preserves
the last valid configuration. Deleting it restores the base setup options.
External edits are checked on focus/buffer events. Arbitrary Lua files are never
executed as hot configuration, and package updates never overwrite this file.

LUA API                                                           *nvim-zh-api*

The public module exposes only the following functions. Internal nvim-zh.*
modules are not stable plugin APIs.

status()        Return a deep-copied snapshot of effective configuration,
                running/installed versions, resources, native/Help/UI/plugin/
                diagnostic/LSP state, and runtime task state. Queries do not
                implicitly setup, install, update, generate locales, or write.

translate(spec) Return text, status, entry_id. spec accepts domain, optional
                context, msgid, optional args/formatted/translated/observe.
                Exact entries precede anchored templates. status is translated
                or fallback; unknown/ambiguous/error cases return the source.

register_catalog(domain, loader, metadata?)
                Register a lazy catalog. loader returns schema=1, domain,
                locale, and entries. User overrides merge after built-ins.

register_adapter_source(id, directory)
                Register a plugin source directory before its modules load
                when using a mirror or a different manager. Standard vim.pack
                installations are identified by the manifest repository URL.

register_adapter(definition)
                Register an external adapter and return its release function.
                See docs/api.md for the definition format.

stats()         Return loaded catalog entry counts and this process's actual
                observed/fallback/missing statistics. These are not global
                localization coverage or fixture hit rates.

missing()       Return bounded, sorted, redacted missing entries. Dynamic text,
                paths, and long messages use SHA-256 labels. Memory only.

open()          Open/focus the panel and return its window. Return nil, error
                when no UI is attached.

check(callback?) Start a read-only check and return a task id. The callback
                receives ok/status/error_code/error/task_id/results. status is
                ok, degraded, error, or cancelled. A superseded pending check
                receives cancelled/superseded; teardown uses cancelled/stopped.

refresh(callback?) Reconcile local configuration, registered catalogs, and the
                current installed resources. Return a task id. The callback
                additionally receives restart_required. This never downloads,
                changes vim.pack locks, or selects another revision. Manual
                refresh is not required for ordinary vim.pack updates.

teardown()      Cancel pending work, close the panel, and restore only state
                still owned by nvim-zh. Later external replacements are not
                reclaimed.

UI AND THIRD-PARTY PLUGINS                                      *nvim-zh-plugins*

notify_once deduplicates the English source before notification. input/select
preserve opts, callbacks, asynchronous order, raw input, and item/index.
select_items wraps only format_item. echo preserves chunk highlights/metadata,
history, opts, and message ids; fast events bypass translation.

Notification sources are registered by exact public opts.title. Fixed plugin
prefixes and their whitespace are preserved. Unknown titles use nvim-ui;
unknown messages fall back without a second translation/observation.

which-key translates presets, generated counts, footer hints, marks/Register
labels, notifications and health reports. replace.desc receives only the
description string, so identical user descriptions can display the same
translation. The original mapping stays intact.

Telescope translates initial and dynamic titles, refine and keymap popups,
Git and Register prompts, notifications and health reports. Internal picker
titles, paths, entries, queries and callbacks keep their source values.

nvim-tree translates default on_attach mapping suffixes and preserves the
ASCII `nvim-tree: ` prefix. It also translates file operations, file info,
the Window picker, the help popup and hidden counts. Custom descriptions and
commands registered by the plugin retain their upstream metadata.

nvim-dap translates structured selectors, REPL help, fixed input prompts,
breakpoint quickfix text, widget states, notifications and health reports.
REPL command tokens, protocol objects, logs, debugger output and variables
retain their source values. launch.json descriptions and the default Input
prompt fall back to upstream text.

nvim-dap-ui translates fixed render text, mappings, float titles, element and
Window selectors, and notifications. Variables, expressions, frames, paths,
protocol objects and debugger output retain their source values.

nvim-dap-view translates default tabs and keymap descriptions, empty views,
g?, input prompts and jump choices, notifications, configuration errors,
and recognized CodeLLDB labels. Enable nvim-zh or register the source before
loading dap-view. See |dap-view.txt| for the full Chinese help.

lazy.nvim supplies the User LazyLoad lifecycle event. nvim-cmp completion data
comes from completion sources or user formatters. See manifests/adapters/ and
docs/adapters.md for fixed revisions, source digests and supported features.

DIAGNOSTICS AND LSP                                         *nvim-zh-diagnostics*

With the clangd pack installed, common clangd, Clang, and clang-tidy diagnostics
appear in Chinese in virtual text, virtual lines, floats, and Neovim diagnostic
lists. diagnostics.lists
controls quickfix and location list translation. vim.diagnostic.get() and
user_data.lsp retain the original messages and locations.

lsp.messages and lsp.progress control notifications and work progress.
lsp.hints covers code action titles, hover labels, signature titles, and native
completion descriptions. Code action menus use ui.prompts. Edits, completion
insertions, code, and LSP protocol records retain their original values.
Diagnostics and hints missing from the catalog retain their original text.

C/C++ WORKFLOW                                                     *nvim-zh-cpp*

Install the clangd localization pack with :NvimZhPacks. Use |:NvimZh| to inspect
the version and fallback state. Apply a fix with |vim.lsp.buf.code_action()|,
review the resulting edit, and save the file.

Clang compiler display uses the results that Neovim parsed for :make or
:lmake. Use the existing errorformat or select the optional parser: >vim

    :compiler nvim-zh-clang
    :setlocal makeprg=clang++\ -std=c++20\ -fsyntax-only
    :make! %
    :copen
    :NvimZhRaw
    :cc
    :echo v:shell_error
<
                                                              *:NvimZhRaw*
Inspect the selected quickfix/location entry, including its source text,
tool code and tool version when available.

                                                       *:NvimZhDiagnosticRaw*
Read the source diagnostics and codes on the current source line.
|vim.diagnostic.get()| also returns the LSP object in user_data.lsp.

For standalone checks, use :compiler nvim-zh-clang-tidy and makeprg=clang-tidy.
Inspect the finding, run clang-tidy with --fix when ready, and check again
without --fix. The compiler module controls list display. clangd diagnostics
forwarded from clang-tidy can use the corresponding clang-tidy catalog.
See docs/toolchain-coverage.md for the pinned combination and current gaps.

HELP DOCUMENTS                                                  *nvim-zh-help*

Chinese translations ship as .cnx files with prebuilt tags-cn. The default
'helplang' is cn,en, so missing tags fall back to English. Use `:help <tag>@en`
to select the English runtime document explicitly.

Per-document upstream commit, source path, SHA-256, and complete/partial status
are machine-recorded in manifests/upstreams.json and help_inventory.json.
Structural tag/example/link checks and manifest status do not claim semantic
review or complete Neovim localization.

doc/nvim-zh.txt and doc/nvim-zh.cnx are project-owned help, not upstream Neovim
translations and not included in the upstream document count.

MAINTENANCE                              *nvim-zh-maintenance* *nvim-zh-resources*

See CONTRIBUTING.md and docs/testing.md for editing sources, test categories,
and optional real upstream checks. Common maintainer commands: >

    make check-syntax check-translations check-native
    make build-resources check-resources
    make test
    make test-upstream
    make check-reproducible release-check
<
Generated Lua catalogs, MO files, help indexes, inventory, and resources are
never hand-edited. Package users need none of these commands.
