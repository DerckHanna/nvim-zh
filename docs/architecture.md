# 架构

首节描述以任务验收的产品目标。后续章节记录当前实现和发布资源。

## 完整中文工作体验

`nvim-zh` 的产品目标是让使用简体中文的人在 Neovim 里完成开发、写作和日常编辑。从启动、查找和编辑，到理解诊断、运行任务、调试和排错，用户沿用熟悉的命令和交互，在原来的位置看到自然、可操作的中文。需要查阅上游文档或报告问题时，可以取得对应的英文原文、错误码和版本信息。

**完整性按工作任务验收。** 每个已声明支持的任务都应覆盖操作入口、首次反馈、成功与失败提示、下一步操作及关联帮助。必经环节若只有英文且缺少足以继续操作的中文指引，该任务记为部分覆盖。发布说明列出实际通过的任务、平台与版本组合。词条数量可衡量翻译维护量，任务是否完整由实际交互验证。

### 用户任务与本地化范围

| 工作任务 | 用户应能用中文完成的环节 | 主要入口 |
| --- | --- | --- |
| 启动、配置与恢复 | 读懂欢迎信息、配置错误、插件更新提示和健康检查，找到出错项及恢复方法 | Neovim gettext、runtime 文案、`:checkhealth`、中文 Help |
| 查找、编辑与写作 | 搜索和打开文件、查找替换、理解补全和重命名提示、操作 Buffer 与 Window，并顺畅录入及编辑中英混排内容 | 核心交互、内置 UI 和已选的检索或补全插件 |
| 理解代码并修复问题 | 读懂诊断、悬浮说明、代码动作与语言服务进度，定位错误并确认修复结果 | 原生诊断和 LSP UI，语言工具汉化包 |
| 构建、测试与调试 | 看到任务状态、失败位置、测试结果和调试操作，能从错误或堆栈跳回源代码 | `:make`、quickfix、任务工具、DAP 界面及中文排错指引 |
| 版本控制与协作 | 理解差异、分支操作、冲突和确认提示，按原来的流程提交和排错 | Neovim diff、Git 工具支持和可选插件包 |
| 学习与查阅参考 | 用中文关键词找到操作指南，从界面跳到对应 Help 和错误说明 | 中文任务索引、`.cnx`、原有 `:help` tag 与对应英文主题 |

### 主包与可选资源

主包应交付安装后即可离线使用的基础能力。Neovim 自己拥有的核心消息使用 gettext，公开的 Lua 与 runtime 界面优先走上游本地化接口或经验证的显示入口。随包交付核心 Help、错误码索引、中文入门和通用 UI。缺少稳定接入点的核心文本应跟进上游，已有的核心能力继续使用版本化资源快照。

外部插件、语言服务器、编译器、测试运行器、调试器和 Git 集成都可按需安装汉化资源。官方包作为 `nvim-zh` 同仓库的 GitHub Release 附件分发，由 `nvim-zh` 按用户选择下载。它们共用发布索引、安装登记、版本选择、离线导入和回滚。包清单增加目标类型，插件包按仓库和已加载模块验证，工具包按工具标识、版本与所用接口或输出 schema 验证。一个包可以只提供词库、诊断说明或中文帮助，也可以包含经过授权的接入代码。实际工具和插件沿用用户自己的安装与配置。网络只用于显式的包管理操作。[可选汉化包设计](adapter-system-design.md#由-nvim-zh-管理的可选汉化包)

任务清单把所需能力、可选包和已验证组合关联起来。例如「C/C++ 开发」可连接核心编辑与 quickfix、`clangd` 诊断、构建工具以及用户选用的调试界面。状态面板按任务提示当前能完成哪些环节、哪个包或版本缺失、哪些界面会回退。用户在面板的「汉化包」页查找、安装和更新所需资源，任务清单负责解释依赖与覆盖。[TUI 汉化包管理设计](adapter-system-design.md#tui-汉化包管理)

### 工具链如何呈现中文

| 工具输出 | 接入方式 | 需要验证的原始行为 |
| --- | --- | --- |
| 显式支持中文的工具界面 | 使用工具提供的语言选项或官方语言包，在可确认安全的调用范围内设置消息语言 | 参数、退出状态和机器可读输出符合调用契约。工具语言配置的作用范围限定在用户授权的调用或客户端 |
| LSP、编译器、测试工具、DAP 的结构化结果 | 在 Neovim 展示时根据来源、稳定编号或已验证模板翻译说明文字；含义随版本变化时校验输出版本与字段 | 诊断范围、severity、编号、跳转、代码动作、测试标识、线程、栈帧、变量及协议对象保持原值 |
| `:make` 或任务运行器的文本输出 | 先由原有解析规则产生 quickfix、位置或状态，再为列表和详情提供中文显示。无法验证的文字使用原文，可按来源和错误码查阅中文解释 | `errorformat`、quickfix 原始项、`user_data`、退出状态、日志与重跑语义一致 |
| `:terminal` 中的交互程序 | 由终端中的应用使用自己的中文 locale；Neovim 提供中文终端操作帮助。受支持工具的诊断可在结构化列表中查看中文 | PTY 字节流、ANSI 控制序列、终端输入和任意程序输出原样交付 |

Neovim 的核心消息语言按会话启用。外部作业沿用用户配置的环境，显式选用的工具入口才为受支持的调用传入消息语言。翻译层选用由来源拥有的消息键和已验证的模板，再填入原始参数。悬浮窗中的项目注释、依赖文档和用户内容按原文显示。以 clangd 的未声明标识符为例，诊断浮窗可显示「未声明的标识符 `counter`」，跳转和代码动作从原始诊断取得位置与参数。详情可查看诊断原文和错误码并复制用于搜索或报告。工作链上缺少译文时，状态区分缺词条、版本未验证和无可接入接口。

### 中文交互与帮助

- **输入与渲染。** 验收中文路径、搜索词、中英混排粘贴、撤销、宏回放、浮窗宽度、换行、光标和高亮定位。终端或 GUI 客户端负责输入法候选和预编辑。验收分别记录 UTF-8 输入后的编辑行为，以及实际客户端的输入法体验。
- **中文文档。** 中文 Help 覆盖核心概念和常用错误，按任务补充可执行的中文操作指引。沿用 `:help` tag、命令名、选项名、快捷键和代码示例。中文索引为日常术语提供检索别名，条目可跳到匹配的中文或英文 Help。术语表在构建与审阅时保持核心和资源包措辞一致。
- **遇错可继续。** `:NvimZh` 汇总当前工作流的覆盖、降级原因和待重启状态，`checkhealth` 给出可操作的中文排错步骤。未知来源和未知版本保留原显示。缺失记录以现有本地脱敏机制为基础，按任务与来源归类，便于维护者补齐高频阻断项。

### 首个端到端验收场景

先以仓库现有的 Neovim 0.12.6、Linux/glibc + LuaJIT 为参考环境，锁定 clangd、构建工具和一套已有真实调试测试的 DAP 组合。用同一个小型 C/C++ 项目跑完以下流程。

1. 从干净会话启动，通过中文 Help 找到操作步骤，在含中文路径的项目里搜索、打开并编辑文件。
2. 引入已知编译错误，在诊断浮窗读懂中文说明，按既有命令跳到正确位置修复，并查看同一诊断的原文和错误码。
3. 运行失败和成功两轮构建或测试，从中文状态和 quickfix 定位结果，再启动调试、命中断点、检查变量并继续执行。
4. 移除一个可选包，或将目标切到未验证版本，重复相关操作，检查原文回退、中文状态提示与原有行为。更新并回滚资源后，再次执行任务并记录实际版本组合。

在真实 TUI 验证首次显示、中文宽度、截断和光标对齐，并与关闭汉化的会话对照选中项、跳转位置和操作结果。结构化断言同时比较命令、数据对象、退出状态与产生的文件。逐任务记录必经显示面是否通过、剩余原文来自哪里，以及是否影响完成任务。平台能力和客户端分别验收，macOS、Windows 与其他运行环境以各自的原生消息探针和真实交互结果公布支持。

### 交付顺序

1. **先完成零可选包的体验。** 以启动、编辑、中文 Help 和健康检查为主线补齐核心消息及 runtime 界面，验证中文路径、布局、失败恢复和保留英文错误码。建立用户任务清单和发布门禁。
2. **打通 C/C++ 开发闭环。** 接入 `nvim-zh` 管理的可选包，选用 Telescope 验证外置插件包，再用现有 clangd 适配验证同一管理器能够交付工具包，保留 `clangd` domain 和用户覆盖。接着覆盖构建、quickfix 和一套完整调试链路。
3. **按任务扩展覆盖。** 先补齐测试失败和 Git 冲突等关键路径，再将同一契约用于其他语言工具和工作流。每新增一个受支持的组合，同步发布其中文操作指南、上游版本、回退方式和端到端证据。

## 目标与边界

nvim-zh 由五类输入组成：

| 输入 | 位置 | 是否随包更新 | 运行时如何使用 |
|---|---|---|---|
| 插件实现 | `plugin/`、`lua/nvim-zh/` 中非生成 Lua | 是，由 vim.pack 管理 | 当前进程冻结同一份实现；实现变化提示重启 |
| 翻译编辑源 | `translations/` | 由维护者修改 | 构建为只读目录和 MO，不在安装端执行构建 |
| 中文 Help | `doc/*.cnx`、项目自有 `nvim-zh.txt/.cnx` | 是 | 与预生成索引进同一资源快照 |
| 发布资源 | `resources/` | 是 | 全量校验后发布为不可变快照 |
| 用户输入 | `setup(opts)`、`stdpath('config')/nvim-zh.json` | 否 | 与默认配置分层合并，不被包更新覆盖 |

`build/` 是维护端缓存和中间产物，不是安装端的输入。开发目录不会被复制或同步到用户已经安装的插件目录。

## 运行时职责

```text
用户命令 / Lua façade
        │
        ├── session ───────────────┐
        │                          │ 应用、恢复配置与适配器
        ├── runtime ───────────────┤
        │   ▲                      │ 同步、排队、取消、包事件
        │   │                      ▼
        │   └─ config_file / resources / native_backend
        │
        └── status ◄───────────────┘
             ▲
             ├── health（只读检查）
             └── tui（状态和包管理）

translate / register_catalog ──► catalog / engine / missing
```

- **`init.lua`**：公共 façade，只负责参数转发，不藏业务流程。
- **`session.lua`**：保存基础配置和当前有效配置，按固定顺序应用或恢复模块；不知道包事件和面板。
- **`runtime.lua`**：唯一同步协调器。setup、配置保存、有限补检和 `PackChanged` 都进入同一队列，处理重入、取消、错误和完成通知。
- **`resources.lua`**：验证清单和内容哈希，准备不可变资源快照，冻结当前实现，发布活动资源状态。它不下载、不选择版本、不修改 vim.pack 锁文件。
- **`native_backend.lua`**：管理 gettext 绑定、消息语言和私有 locale 能力，只恢复仍由本插件拥有的进程状态。
- **`catalog.lua` / `engine.lua`**：精确目录、受控模板、用户覆盖和原文回退；不知道第三方插件生命周期。
- **`ui.lua` / `diagnostics.lua` / `lsp.lua`**：Neovim 自身公开显示接缝，保留原对象、回调和外部函数所有权。
- **`plugins.lua` / `adapters/`**：适配注册、加载证据和通用显示接缝。插件专用适配器随可选包交付。
- **`packs.lua` / `pack_store.lua`**：协调下载、选版、启停与回退，校验并发布不可变包快照，按代次更新包登记。
- **`status.lua`**：组合只读快照。查询不会隐式 setup、安装、更新、生成 locale 或写缓存。
- **`health.lua`**：异步或同步只读检查，区分通过、降级、失败、未检查、不支持和取消。
- **`tui.lua` / `packs_ui.lua`**：将快照绘制到 scratch Buffer，向包管理器提交用户选中的操作。

模块可以依赖下一层能力，但不得通过 `require('nvim-zh')` 回到公共 façade 形成循环。

## 配置与翻译数据

配置校验只接受已知字段和纯数据覆盖。默认配置、`setup(opts)` 和本地 JSON 按固定优先级合并；应用失败时恢复上一份完整有效状态。配置与翻译数据不包含可执行 loader。

翻译按 `domain + context + msgid` 查询。静态条目优先，动态文本只匹配锚定且占位符兼容的模板；歧义、未知文本和目录错误回退原文。没有全局模糊替换、任意 Buffer 扫描或最终文本术语替换。

## 第三方适配

每个适配器负责：

1. 检查目标模块已经加载，不强制加载依赖；
2. 验证实际公共接口形状；
3. 只复制并修改显示字段，保留条目身份、回调、参数、快捷键和用户数据；
4. 记录自己的 wrapper/formatter，重复 setup 不叠加；
5. 外部后来替换同一函数时报告 `external_override`，不重复包装或抢回所有权；
6. teardown 只恢复仍由本插件持有的函数；
7. 返回可诊断的 `active/reason/seam` 状态。

固定源码接缝由加载器核对实际执行的模块字节、模块身份和更新代次。上游更新使旧代次失效，缺证据时该接缝返回上游文案。Help 按实际上游文档摘要启用。清单、接缝状态和回退规则见[适配系统设计](adapter-system-design.md)。

通知采用内部的精确来源注册：适配器按公开 `opts.title` 注册 domain，公共 UI 在调用原通知实现前完成一次翻译。固定前缀和空白原样保留，未知 title 仍走 `nvim-ui`，避免插件层与公共层重复翻译或制造伪缺失记录。

## 资源同步与重启判定

一次同步按以下顺序执行：

1. 读取本地配置和已安装资源清单；
2. 校验所有候选文件、路径、哈希、目录 schema、Help 引用和 MO 哨兵；
3. 在唯一临时目录准备候选，并以原子重命名发布不可变快照；
4. 预备目录与 Help 切换，应用配置和各适配器；
5. 启动或更新原生后端；
6. 全部成功后发布活动状态；任一步失败按所有权补偿旧目录、Help、配置和资源状态。

资源与实现分别计算内容标识：

- PO、生成的 JSON/Lua 目录、Help、MO 或 `VERSION` 变化只改变资源集，不单独要求重启。
- 非生成运行 Lua、插件入口或生成的适配索引变化会改变实现标识。当前进程继续使用已加载的实现并提示重启。
- 下次启动从 vim.pack 选中的安装修订加载新实现，并自动完成资源同步，无需手动 Reload。

旧实现遇到未知资源格式时保留旧资源并提示重启。纯资源更新不通过清空全部 `package.loaded` 热执行新代码。

## 所有权、并发与缓存

- 同一 Neovim 进程的同步请求进入单个协调器，重复事件合并，回调在最终完成或取消时收到明确结果。
- 多进程用唯一临时目录和原子发布复用相同内容快照；不删除其他进程或旧 Help 视图仍可能使用的历史快照。
- 用户配置、覆盖、私有 locale 和资源缓存都在各自用户目录，不写开发目录或系统目录。
- 私有 locale 按 libc 与架构隔离；异步准备完成后再次检查所有权和任务代次，避免覆盖外部语言或绑定变化。
- 面板静态页由状态事件驱动，动态统计页限频刷新；关闭面板不影响后台同步。

## 编辑源与生成物

- `translations/po/zh_CN/*.po` 经 `catalog_tool.py` 生成 Lua 目录，并经 `resource_bundle.py` 生成随包 JSON 目录。
- `translations/native/*.po`、固定上游缓存和修复清单经 `native_catalog.py` 生成合并 MO。
- `doc/tags`、`doc/tags-cn` 由 Neovim `:helptags` 生成。
- `manifests/help_inventory.json` 由 Help 清单工具生成。
- `manifests/adapters/` 为独立包提供运行清单和固定上游验收输入，生成的维护索引位于 `manifests/adapter-index.lua`。
- `resources/` 由完整资源构建器确定性生成，包含内容哈希与资源摘要。

生成文件不手工编辑。运行用户不需要 Python、gettext 工具、帮助索引生成命令或构建 hook。
