# 架构演进

## 运行时契约

nvim-zh 在显示边界应用译文。命令、用户输入、诊断和协议对象仍由上游处理。显示面需要可验证的来源与所有权。无法确认来源、版本或回调归属时，沿用上游显示。详见[架构](architecture.md)与[适配契约](adapter-system-design.md)。

| 范围 | 当前设计 |
| --- | --- |
| 同步 | 由运行时协调器串行处理本地配置、资源与包变更。每次应用使用完整验证过的快照，失败时保留可用状态。 |
| 词库 | 按 domain、context 和 msgid 索引，用户覆盖独立于原词库。可选工具词库延迟加载。 |
| 汉化包 | SDK 2 将词库内嵌在 UTF-8 JSON 附件内。发布索引和附件共享一套摘要与结构验证。Lua 或接入契约变化后在下一次启动成对启用实现和数据。 |
| 构建与列表 | 使用发起窗口、工作目录和完整列表 ID 关联构建与投影。异步探测核对可执行文件指纹。 |
| LSP | 通过真实 namespace、Buffer、客户端与方法确定诊断来源，进度按客户端和 token 追踪。补全插入数据沿用上游值。 |
| DAP | REPL 的临时状态随协程与会话。Scope 请求捕获会话与帧，只有仍拥有面板的结果可更新显示。 |

## 扩展验证

更新 Neovim、插件或工具版本时，先记录实际参与显示的源码或二进制摘要，再验证启停对照。测试应覆盖首次渲染、跨窗口或跨会话隔离、外部覆盖、清理以及原始数据一致性。涉及包的更新需要验证冻结、损坏回退与离线回滚。见[测试文档](testing.md)。

此前的 P0–P2 方案、性能基线与实验记录保存在 [v0.2.0 的演进设计](https://github.com/DerckHanna/nvim-zh/blob/v0.2.0/docs/evolution-design.md)。本版结果见[验证记录](verification.md)。
